# Среда исполнения и внешние границы

## Purpose

Спецификация определяет согласованное поведение RunnerAgent в области «Среда исполнения и внешние границы» для первого C++23 MVP и его проверку.

## ADDED Requirements

### Requirement: REQ-04 — Состав Linux-образа

RunnerAgent SHALL исполняться в согласованном Linux privileged Docker-образе с .NET 10, isolate и g++.

#### Scenario: REQ-04 — согласованный контракт

- **WHEN** агент развёртывается в среде MVP
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Принято 6 ноября 2026 года: поставка состоит из базового образа (Linux, .NET runtime, isolate, агент, общий bootstrap) и производных образов с toolchain/runtime конкретного языка и фиксированной конфигурацией раннера. Базовый образ без профиля не принимает задания; первым готовым worker остаётся C++23. Конкретный профиль определяется образом, а не запросом RunJob. Слои compiler/runtime и их конфигурация проверяются вместе с тем базовым образом, который будет опубликован.

MVP должен работать в Linux Docker-контейнере с `--privileged`, содержащем .NET 10 Runner Agent, isolate, g++, compiler/runtime libraries и локальную временную рабочую область. Обозначение `judge-cpp` описывает состав первого образа; согласованный registry package — `ghcr.io/texnokaktus-progolymp/runner-agent-cpp-23`. Для JIT-образа требуется .NET runtime.

```text
Мастер -- gRPC HTTP/2 --> RunnerAgent
                             |
                             +-- MinIO: исходный код, входные данные, артефакты
                             +-- isolate: одна компиляция
                             +-- isolate: отдельный запуск каждого теста
Мастер <-- результат и ссылки на S3 --+
```
#### Scenario: AT-28 — Образ и секреты

- **WHEN** исследуется состав образа и доступность build/runtime secrets
- **THEN** Linux-образ содержит agent/isolate/toolchain; секреты не записаны в build args/слои и не попадают в sandbox

Связанные требования: REQ-04, REQ-19, REQ-28.


### Requirement: REQ-05 — Границы gRPC и S3

RunnerAgent SHALL передавать управление через HTTP/2 gRPC, а содержимое файлов через S3; endpoint настраивается.

#### Scenario: REQ-05 — согласованный контракт

- **WHEN** мастер обменивается заданиями и файлами с агентом
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

gRPC используется для управления и небольших структурированных результатов. Исходный код, stdin, stdout, stderr и вывод компилятора передаются через S3, а не через gRPC. В MVP gRPC работает по HTTP/2 без HTTPS/TLS и аутентификации в доверенной внутренней сети. По умолчанию агент слушает `0.0.0.0:8080` внутри контейнера; адрес прослушивания и порт должны настраиваться.
#### Scenario: AT-37 — Endpoint агента

- **WHEN** агент запускается с endpoint по умолчанию либо переопределённым
- **THEN** По умолчанию агент слушает `0.0.0.0:8080` внутри контейнера по HTTP/2 без TLS; настройка адреса и порта меняет endpoint

Связанные требования: REQ-05.


### Requirement: REQ-06 — MinIO и credentials агента

RunnerAgent SHALL использовать MinIO через согласованный клиент и только environment credentials с локальной startup-валидацией.

#### Scenario: REQ-06 — согласованный контракт

- **WHEN** агент запускается и обращается к MinIO
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Файловое хранилище — MinIO. Агент обращается к нему через `AWSSDK.S3` за интерфейсом `IObjectStorage`; endpoint берётся из конфигурации, используется `ForcePathStyle = true`. Credentials принадлежат только агенту: provider читает `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и необязательный `AWS_SESSION_TOKEN` из окружения агента, без поиска в профилях или metadata-сервисах. Отсутствие обязательных значений — ошибка конфигурации при запуске. Выбор environment credentials принят при обязательной изоляции секретов по REQ-19.

Регион подписи клиента по умолчанию — `us-east-1`, с возможностью переопределения в конфигурации агента. В текущем развёртывании пользователя регион на сервере MinIO явно не задан; перенастройка сервера для работы агента не требуется. Совместимость выбранных версий MinIO/SDK проверяется интеграционно, в том числе на сервере без явно заданного региона. Версия SDK и оставшиеся настройки относятся к Q-08.

При запуске проверяется локальная конфигурация storage, включая обязательные credentials. Сетевая доступность MinIO, существование bucket и права доступа проверяются рабочими операциями по согласованной политике повторов. Обязательных сетевых проверок storage при запуске нет; временная недоступность MinIO сама по себе не препятствует запуску агента. Проверка локальной sandbox-среды по [разделу 6](../sandbox-execution/spec.md) остаётся обязательной.

Privileged Docker служит упаковкой и способом запуска, но не самостоятельной security boundary. Основная техническая граница для кода решения — isolate. Существенный риск компрометации judge-host принят для первого этапа. Контейнер дополнительно ограничивается по CPU, RAM и числу процессов там, где это совместимо с isolate и cgroups.

Целевое развёртывание — отдельная заменяемая Judge VM либо выделенный host с native isolate, cgroup delegation, минимальными привилегиями и изолированными toolchain/rootfs. Переход должен сохранять внешний gRPC/S3-контракт и логику orchestration. Подбор capabilities, user namespaces и cgroup delegation внутри Docker не входит в MVP.

#### Scenario: AT-64 — Path-style MinIO

- **WHEN** production-клиент обращается к MinIO
- **THEN** Production-клиент использует настроенный endpoint и адресацию bucket в пути (`ForcePathStyle = true`)

Связанные требования: REQ-06.

#### Scenario: AT-65 — Регион подписи MinIO

- **WHEN** сервер MinIO не имеет явно заданного региона либо регион клиента переопределён
- **THEN** Значение клиента по умолчанию `us-east-1` работает с MinIO без явно заданного серверного региона; переопределение региона применяется к подписи запросов

Связанные требования: REQ-06.

#### Scenario: AT-66 — Storage при запуске

- **WHEN** MinIO недоступен при старте с корректной локальной конфигурацией либо отсутствуют credentials
- **THEN** Корректная локальная конфигурация позволяет запуститься при недоступном MinIO без обязательных сетевых проверок; последующие рабочие операции используют согласованные повторы. Отсутствующие обязательные credentials не позволяют запуститься. Агент не создаёт bucket и не меняет их настройки

Связанные требования: REQ-06, REQ-15, REQ-17.

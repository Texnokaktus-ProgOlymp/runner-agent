# S3 и целостность файлов

## Purpose

Спецификация определяет согласованное поведение RunnerAgent в области «S3 и целостность файлов» для первого C++23 MVP и его проверку.

## ADDED Requirements

### Requirement: REQ-15 — Bucket и ключи артефактов

RunnerAgent SHALL выбирать два настроенных bucket по ролям и формировать выходные ключи в префиксе мастера.

#### Scenario: REQ-15 — согласованный контракт

- **WHEN** агент получает входы и публикует артефакты
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Конфигурация агента должна задавать два bucket:

| Роль | Bucket | Ссылка во входном задании или результате |
| --- | --- | --- |
| Исходный код | Отдельный bucket исходного кода | Входные `key` и ожидаемый `sha256` |
| Вход теста | Общий bucket данных и артефактов | Входные `key` и ожидаемый `sha256` |
| Stdout и stderr компилятора | Общий bucket данных и артефактов | Отдельные фактические выходные `key` и вычисленный `sha256` каждого потока |
| Stdout и stderr тестов | Общий bucket данных и артефактов | Фактические выходные `key` и вычисленный `sha256` |

Bucket создаются заранее при развёртывании. Агент их не создаёт и не меняет их настройки. Bucket выбирается агентом по роли объекта. Для выходных файлов ключи формируются внутри `result_prefix` мастера с согласованными суффиксами:

| Артефакт | Путь внутри `result_prefix` |
| --- | --- |
| Stdout компилятора | `compilation/stdout.txt` |
| Stderr компилятора | `compilation/stderr.txt` |
| Stdout теста | `tests/{test_id}/stdout.txt` |
| Stderr теста | `tests/{test_id}/stderr.txt` |

В ключах используется исходный номер теста. Мастер должен выдавать новый `result_prefix` для каждого запуска, включая повторное выполнение задания. Агент не ведёт реестр использованных префиксов и не выполняет дополнительных проверок существования выходных объектов; загрузка может перезаписать объект по тому же ключу, если мастер повторно использовал префикс. Уникальность обеспечивает мастер. Агент возвращает фактические ссылки на опубликованные объекты.

Входные `key` и `result_prefix` должны быть непустыми; пустое значение даёт `INVALID_ARGUMENT`. Завершающий `/` в `result_prefix` допускается. При формировании выходного ключа между префиксом и согласованным суффиксом добавляется `/`, только если префикс ещё не заканчивается `/`. S3-ключи не используются как локальные пути; размещение локальных файлов определяет агент.

Отдельные лимиты размеров исходного файла и входных файлов тестов не вводятся. Resource limits компиляции и исполнения сохраняются.
#### Scenario: AT-17 — S3-контракт

- **WHEN** агент получает входы и публикует результаты в S3
- **THEN** Используются два настроенных bucket по ролям; выходные ключи находятся внутри префикса мастера, возвращаются фактические ссылки и hash

Связанные требования: REQ-06, REQ-15, REQ-16.

#### Scenario: AT-49 — Валидация и формирование ключей

- **WHEN** передан пустой ключ/префикс либо префикс с завершающим слешем и без него
- **THEN** Пустые `key`/`result_prefix` дают `INVALID_ARGUMENT`; префиксы `run` и `run/` формируют одинаковый ключ для одного суффикса; S3-ключ не используется как локальный путь; отдельной проверки существования выходного объекта нет

Связанные требования: REQ-15.


### Requirement: REQ-16 — Целостность SHA-256

RunnerAgent SHALL проверять входные SHA-256 до использования и возвращать выходные хеши как 32 байта.

#### Scenario: REQ-16 — согласованный контракт

- **WHEN** входной объект скачан или выходной артефакт подготовлен
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

После скачивания входного объекта агент должен проверить SHA-256 до помещения файла в sandbox. Несовпадение hash — ошибка подготовки; такой файл не запускается и не используется при компиляции. ETag не заменяет SHA-256. Контракт не использует `version_id` и не требует включения S3 versioning. Для выходных артефактов агент вычисляет и возвращает SHA-256.

`sha256` передаётся как массив ровно из 32 байт хеша, одинаково для входных ссылок и выходных артефактов; в protobuf используется `bytes`. Текстовое hex-представление не используется. Неверная длина входного `sha256` является ошибкой валидации запроса (`INVALID_ARGUMENT`); несовпадение корректно заданного хеша с содержимым скачанного объекта является ошибкой подготовки согласно REQ-16. При сравнении повторных заданий сравнивается содержимое массивов байт.
#### Scenario: AT-18 — Целостность

- **WHEN** hash входного файла не совпадает с ожидаемым
- **THEN** Неверный SHA-256 блокирует использование файла; ETag не подменяет hash; versioning не требуется

Связанные требования: REQ-16.

#### Scenario: AT-47 — Формат SHA-256

- **WHEN** передаются, проверяются и сравниваются входные и выходные SHA-256
- **THEN** Входные и выходные хеши представлены 32 байтами; неверная длина во входном запросе даёт `INVALID_ARGUMENT`; содержимое массива корректно проверяется и сравнивается при повторе задания

Связанные требования: REQ-07, REQ-08, REQ-16.


### Requirement: REQ-17 — Повторы и частичная публикация

RunnerAgent SHALL управлять ограниченными повторами MinIO, продолжать частичную публикацию и сохранять опубликованные объекты.

#### Scenario: REQ-17 — согласованный контракт

- **WHEN** storage-операция завершается успешно либо с ошибкой
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Политикой повторов скачивания и загрузки MinIO управляет агент. Для каждой операции допускается не более трёх попыток всего, включая первую; задержки перед второй и третьей — 200 мс и 500 мс соответственно. Автоматические повторы `AWSSDK.S3` отключаются, включая дополнительные механизмы повторов выбранной версии SDK; скрытые повторы не должны увеличивать число попыток.

Повторяются обрывы соединения, сетевые таймауты, HTTP `429`, `500`, `502`, `503`, `504` и S3 `SlowDown`. Неудачное скачивание начинается заново, частичные данные предыдущей попытки не используются. Отсутствие объекта или bucket, отказ в доступе, неверные credentials и несовпадение SHA-256 не повторяются. Отмена самой storage-операции прекращает попытки; отмена RPC по-прежнему не отменяет принятое задание. Прочие ошибки не повторяются, если они не относятся к согласованному перечню временных ошибок.

После исчерпания попыток или неповторяемой ошибки фиксируется инфраструктурная ошибка соответствующей стадии. Ошибка отдельного теста не останавливает остальные тесты. Конкретная библиотека/реализация policy выбирается при реализации без изменения этой семантики.

При неуспешной публикации одного артефакта агент должен продолжить загрузку остальных. Успешно опубликованные объекты не удаляются; результат содержит доступные ссылки и диагностику ошибок по правилам раздела 8. Выходной объект с неуспешной публикацией нельзя обозначать как успешно доступный. Повтор загрузки одного артефакта использует тот же ключ и то же содержимое в рамках согласованного бюджета попыток.

Агент не удаляет опубликованные артефакты, в том числе при частичной публикации, выдаче результата или локальной очистке. Срок хранения и удаление относятся к мастеру или lifecycle-политике MinIO. Решения по S3-контракту закрывают Q-07; оставшиеся параметры клиента уточняются в Q-08, credential provider и политика повторов согласованы в REQ-06 и REQ-17.

#### Scenario: AT-19 — Повторы MinIO

- **WHEN** MinIO возвращает временную либо неповторяемую ошибку
- **THEN** Успешное восстановление и исчерпание временных ошибок укладываются в три попытки с учётом SDK; отсутствие объекта и неверный hash не повторяются

Связанные требования: REQ-17.

#### Scenario: AT-48 — Ключи и частичная публикация

- **WHEN** одна из нескольких публикаций не удалась и повторяется
- **THEN** Ключи используют согласованные суффиксы и исходный `test_id`; сбой одного артефакта не мешает попыткам загрузки остальных; повтор использует прежние ключ и содержимое; опубликованные объекты сохраняются, возвращаются доступные ссылки и диагностика

Связанные требования: REQ-15, REQ-17, REQ-25.

#### Scenario: AT-63 — Повторы storage

- **WHEN** storage возвращает временную/постоянную ошибку или операция отменена
- **THEN** На временные ошибки из согласованного перечня выполняется до трёх попыток с задержками 200/500 мс без скрытых повторов SDK; скачивание начинается заново. Неповторяемые ошибки и отмена не вызывают повторов; отмена RPC не отменяет принятое задание

Связанные требования: REQ-17.

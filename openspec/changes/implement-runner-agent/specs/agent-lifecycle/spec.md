# Состояние агента и жизненный цикл

## Purpose

Спецификация определяет согласованное поведение RunnerAgent в области «Состояние агента и жизненный цикл» для первого C++23 MVP и его проверку.

## ADDED Requirements

### Requirement: REQ-11 — Порядок обработки задания

RunnerAgent SHALL выполнять согласованный pipeline подготовки, компиляции, тестов, публикации, очистки и выдачи результата.

#### Scenario: REQ-11 — согласованный контракт

- **WHEN** задание принято в обработку
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

###### 4.1. Обработка задания

Orchestration должно выполнять следующий порядок действий:

1. Проверить запрос и состояние агента в порядке из [раздела 3.5](../job-api/spec.md); если задание может быть принято, атомарно зафиксировать его принятие.
2. Создать workspace, получить исходный код и необходимые входные данные, проверить SHA-256 до использования файлов в sandbox.
3. Выполнить одну компиляцию с compilation limits в отдельном isolate box.
4. При успешной компиляции выполнить тесты по порядку, создавая отдельный execution sandbox для каждого запуска. Ошибка отдельного теста не прерывает обработку остальных.
5. Собрать результаты и загрузить доступные артефакты в S3, вычислив их SHA-256.
6. Сохранить структурированный результат отдельно от workspace и очистить временные файлы и isolate boxes. При ошибках также выполнить очистку; если сама очистка не удалась, сохранить результаты и их статусы, добавить инфраструктурную диагностику задания и перейти к завершению по разделу 4.4.
7. Ожидать `GetResult`, сохраняя ресурс занятым.
8. Атомарно забрать готовый результат из состояния агента и освободить ресурс до отправки RPC-ответа, затем отправить ответ; при остановке завершить процесс после обслуживания RPC. Обрыв соединения после извлечения не восстанавливает результат.

Порядок предварительного скачивания всех входов либо их получения перед каждым тестом не зафиксирован. Выбранная реализация должна сохранять продолжение набора при сбое загрузки входа отдельного теста.

Для описания долгоживущего агента используются следующие логические состояния; это не утверждённый transport enum:

| Состояние | Что хранится и выполняется | Переход |
| --- | --- | --- |
| Свободен | Нет текущего задания и непрочитанного результата | Принятие задания → обработка |
| Обработка | Задание принято; выполняются подготовка, компиляция, тесты, публикация и очистка | Готовность результата → ожидание чтения |
| Ожидание чтения | Результат хранится отдельно от workspace после успешной очистки либо её ошибки с переходом к завершению | Выдача через `GetResult` → свободен либо завершение при остановке |
| Завершён | Процесс остановлен; состояние в памяти утрачено | При новом запуске восстановление задания не выполняется |

Штатная остановка — отдельный режим, запрещающий принятие новых заданий в состояниях обработки и ожидания. Он описан ниже.

### Requirement: REQ-12 — Неограниченное ожидание результата

RunnerAgent SHALL удерживать ресурс до чтения результата без таймаута в обычном режиме.

#### Scenario: REQ-12 — согласованный контракт

- **WHEN** готовый результат ожидает чтения в обычном режиме
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Во время обычной работы долгоживущего агента ожидание `GetResult` не ограничено таймаутом. Непрочитанный результат не истекает и удерживает ресурс независимо от длительности отсутствия мастера. Завершение вычислений или очистка sandbox сами по себе ресурс не освобождают.
#### Scenario: AT-07 — Очистка и длительное отсутствие мастера

- **WHEN** мастер долго не читает завершённое задание
- **THEN** Workspace/boxes очищены; в обычном режиме результат сохраняется и ресурс занят без таймаута

Связанные требования: REQ-11, REQ-12, REQ-19.


### Requirement: REQ-13 — Состояние в памяти

RunnerAgent SHALL хранить задание и непрочитанный результат в памяти без восстановления после перезапуска.

#### Scenario: REQ-13 — согласованный контракт

- **WHEN** процесс агента перезапускается
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

Для MVP задание и непрочитанный результат хранятся в памяти. Их потеря при перезапуске допустима; сохранение на диск, восстановление и возобновление не требуются. Решение о повторном запуске принимает мастер. Опубликованные S3-артефакты не зависят от памяти процесса.

###### 4.2. Штатная остановка
#### Scenario: AT-25 — Перезапуск

- **WHEN** процесс перезапускается с текущим заданием
- **THEN** Текущее задание и непрочитанный результат не восстанавливаются; опубликованные S3-артефакты доступны

Связанные требования: REQ-13.


### Requirement: REQ-14 — Остановка, повторное использование и очистка

RunnerAgent SHALL завершать принятое задание при остановке, соблюдать таймаут чтения и безопасно обрабатывать начальную и завершающую очистку.

#### Scenario: REQ-14 — согласованный контракт

- **WHEN** агент запускается, завершает задание или получает сигнал остановки
- **THEN** соблюдаются следующие условия (предложения и технические детали сохраняют явно указанный статус):

При запросе штатной остановки агент должен прекратить принятие новых заданий, завершить текущий набор, опубликовать доступные артефакты, очистить sandbox/workspace и сохранить готовый результат для `GetResult`.

Ожидание получения результата при остановке настраивается; значение по умолчанию — **30 секунд**. Отсчёт начинается после готовности результата, публикации артефактов и очистки; при ошибке очистки действует раздел 4.4. Если результат уже готов, отсчёт начинается при запросе остановки. Выполнение задания не расходует этот таймаут.

В течение ожидания gRPC остаётся доступным для `GetResult`. Если результат забран, агент завершает обслуживание RPC, затем останавливает сервер и процесс. Если таймаут истёк, агент выходит с потерей непрочитанного результата в памяти, сохраняя опубликованные S3-артефакты. При отсутствии задания и результата агент может завершиться сразу.

Настройки остановки приложения и контейнера должны позволять завершить задание и затем выдержать ожидание результата. Принудительное или аварийное завершение может привести к допустимой потере состояния. Внутренний `CancellationToken` не означает наличие `CancelJob`; отключение клиента и начало штатной остановки сами по себе не отменяют принятое задание.

###### 4.3. Выбранный жизненный цикл (Q-01 закрыт)

Для MVP выбран долгоживущий агент, обрабатывающий одно задание за раз. Контейнер запускается при развёртывании и используется для нескольких заданий. После выдачи результата через `GetResult` агент должен оставаться запущенным и быть готовым принять следующее задание, если не начата штатная остановка. Завершение одного задания не требует пересоздания контейнера или процесса агента. Отдельные sandbox и очистка после обработки сохраняются согласно REQ-02 и REQ-11. Контейнер на один набор тестов в MVP не входит; компонент управления контейнерами для отдельных заданий не требуется. Автоматический CI-деплой по-прежнему не планируется.

###### 4.4. Очистка при запуске и после задания (Q-10 закрыт)

До приёма заданий агент должен очистить оставшиеся собственные workspace и isolate boxes, включая остатки после падения. Чужие рабочие области и boxes очистке не подлежат. Если начальная очистка не удалась, агент завершает запуск с ошибкой и не принимает задания. Очистка не восстанавливает потерянные задания и результаты.

Если очистка после задания не удалась, агент сохраняет результаты компиляции и тестов, их статусы и общий статус задания, добавляя инфраструктурную диагностику очистки на уровне задания. Он прекращает приём новых заданий и переходит в режим завершения. `GetResult` остаётся доступным в пределах таймаута ожидания результата из REQ-14, по умолчанию 30 секунд. В этом случае отсчёт начинается после подготовки готового результата с диагностикой и завершения попыток публикации и очистки, включая неуспешную попытку очистки; успешное удаление остатков не является условием начала ожидания.

После обслуживания `GetResult` либо истечения таймаута агент завершает процесс. Получение результата не возвращает его к приёму заданий; потенциально неочищенная среда не используется повторно в этом процессе. Новый запуск обязан пройти начальную очистку. Локальная очистка не удаляет опубликованные S3-артефакты. Механизм определения собственных каталогов и boxes задаётся вместе с workspace, box IDs и конфигурацией в Q-09/Q-11.

#### Scenario: AT-22 — Штатная остановка при обработке

- **WHEN** остановка запрошена во время обработки
- **THEN** Новые задания не принимаются; набор завершается, артефакты публикуются, sandbox очищаются, `GetResult` доступен

Связанные требования: REQ-14.

#### Scenario: AT-23 — Таймаут остановки

- **WHEN** остановка запрошена при выполняющемся или уже готовом задании
- **THEN** По умолчанию 30 секунд, значение настраивается; отсчёт после готовности/очистки либо с запроса остановки при уже готовом результате; выполнение задания не расходует таймаут

Связанные требования: REQ-14.

#### Scenario: AT-24 — Выход при остановке

- **WHEN** при остановке результат прочитан либо истёк таймаут
- **THEN** После обслуживания `GetResult` процесс выходит; по таймауту теряет только результат в памяти; незанятый агент может завершиться сразу

Связанные требования: REQ-14.

#### Scenario: AT-29 — Повторное использование агента

- **WHEN** результат первого задания выдан и поступает второе
- **THEN** После выдачи результата первое задание очищено; второе задание с другим ID принимается и обрабатывается в том же процессе и контейнере, если не начата штатная остановка

Связанные требования: [Раздел 4.3](../agent-lifecycle/spec.md), REQ-09, REQ-11.

#### Scenario: AT-50 — Начальная очистка

- **WHEN** перед запуском обнаружены собственные и чужие остатки workspace/boxes
- **THEN** До приёма заданий удаляются только собственные остатки workspace/boxes; при неуспешной очистке запуск завершается с ошибкой без принятия заданий; потерянное задание не восстанавливается

Связанные требования: [Раздел 4.4](../agent-lifecycle/spec.md), REQ-13, REQ-19.

#### Scenario: AT-51 — Ошибка очистки после задания

- **WHEN** очистка после задания не удалась
- **THEN** Результаты и их статусы сохранены вместе с диагностикой очистки; новые задания не принимаются; `GetResult` доступен в пределах таймаута завершения, по умолчанию 30 секунд, затем процесс выходит после обслуживания запроса или по таймауту; среда повторно не используется

Связанные требования: [Раздел 4.4](../agent-lifecycle/spec.md), REQ-14, REQ-19.

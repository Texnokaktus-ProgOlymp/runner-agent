# Исправления архитектурного ревью

Основание: [ревью revision 4a56727](architecture-review.md), AR-01 и AR-02. Исходный отчёт сохраняет наблюдения о проверенной revision; этот документ описывает последующие изменения. Повторное архитектурное ревью поручено двум субагентам с reasoning effort xhigh по указанию пользователя. Это review исходников, а не независимая black-box приёмка.

## AR-01 / REQ-19 — Граница workspace

Linux startup до записи probe канонизирует workspace через libc realpath, включая symlink в родительских каталогах и в целях других symlink. Канонический путь сохраняется в RunnerOptions и передаётся WorkspaceManager. Корень файловой системы и пути внутри реальных источников mounts /usr, /bin, /lib, /lib64, /var/lib/runner-agent-dev отклоняются до открытия API. Сравнение учитывает границы компонентов; похожий префикс /usr-local-* остаётся допустимым. Выделенная realpath-память освобождается через libc free.

Не существующее дерево не может содержать существующий workspace; startup sandbox отдельно проверяет реальную среду. Отсутствующий необязательный mount не мешает host-тестам с заменой внешней среды. Изменение mount topology после проверки и bind-mount aliases остаются ответственностью привилегированного оператора: topology должна быть доверенной и неизменной.

Регрессии: прямой путь /usr/local, merged-usr /bin, источник dev, конечный/родительский/вложенный symlink и ссылка на /; безопасный parent symlink канонизируется с сохранением чужого файла. Реальные Docker-процессы для /usr/local и parent symlink дали exit 1 без Application started. Старый путь чтения sentinel через /usr/local недоступен, поскольку агент больше не начинает обслуживать такие настройки.

## AR-02 / REQ-17 — Точный перечень повторов

HTTP allowlist: только 429/500/502/503/504; отдельный S3-код — SlowDown. HTTP 408/501/505, Throttling/ThrottlingException/RequestTimeout вне HTTP allowlist, произвольная ошибка клиента и статус 0 без сетевой причины больше не повторяются. Разрешены подтверждённые сетевые reset/abort/timeout и преждевременный конец HTTP-ответа, в том числе внутри известных SDK/HTTP-обёрток. Typed TLS/DNS/invalid-response ошибки не становятся временными из-за вложенного socket exception. Отмена токена операции сохраняет приоритет.

Установленный SDK способен раскрыть внутренний TimeoutException HttpClient. Он включён в обработку; реальный SDK с задержанными заголовками первого ответа восстанавливается на второй попытке. Локальные IO-ошибки и обычная отмена без timeout не признаются сетевыми сбоями. Общий бюджет и задержки остаются прежними: три попытки, 200/500 мс, без SDK retries.

Регрессии проходят через production adapter: fake SDK проверяет taxonomy исключений, настоящий SDK/HTTP backend — все HTTP/S3 варианты, число запросов и задержки. Существующая проверка оборванного download подтверждает загрузку с начала и отсутствие Range; проверки hash/403/404/cancellation сохранены.

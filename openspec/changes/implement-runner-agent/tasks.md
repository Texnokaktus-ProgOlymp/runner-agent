# Tasks

Все задачи относятся к будущей реализации MVP и остаются открытыми. Миграция документации не означает их выполнения. Исходная декомпозиция с критериями готовности сохранена в [design.md](design.md#implementation-sequence); детали каркаса — в [repository.md](repository.md). Тесты и документация обновляются вместе с каждым компонентом.

Проверка: выбранные версии отражены в design/repository и позволяют Release restore/build; готовые proto, Docker и MinIO не требуются.
- [ ] 1.2 Создать .slnx, global.json, корневые и групповые props, CPM, editorconfig/gitignore и tool manifest вместе с минимальным production-проектом, net10.0/C# 14 и InternalsVisibleTo. Проверка: Release restore/build, наследование свойств и отсутствие тестовых пакетов в production (REQ-29, AT-27).
- [ ] 1.3 Реализовать entry point, platform/OpenTelemetry, обязательный SERVICE_NAME, настройку и проверку корня workspace в Runner без создания/очистки рабочих областей. Проверка: реальный запуск с допустимой конфигурацией, диагностируемый отказ с недопустимой, штатное завершение незанятого процесса без MinIO/isolate; документировать проверенные команды (OPS-01, OPS-02).
- [ ] 1.4 Подключить .Tests, NUnit/MTP, TRX/Cobertura и ReportGenerator; добавить содержательные тесты валидации и smoke запуска/ошибки/остановки реального процесса. Проверка: dotnet test обнаруживает тесты, ошибка теста возвращает ненулевой код, отчёты создаются; .IntegrationTests добавляется с первым реальным сценарием без пустого проекта (REQ-30).
- [ ] 1.5 Добавить базовый GitHub Actions на push master с Release build/test/smoke, сохранением созданных отчётов при неуспехе и summary; отдельный информационный linux-x64 AOT check не блокирует JIT. Проверка: чистый runner выполняет документированные команды без production secrets, результат реального CI/AOT явно зафиксирован либо отмечен как непроверенный (REQ-27, REQ-31).
- [ ] 1.6 Повторить документированные restore/build/test/run из чистого checkout и согласовать фактическое дерево, версии и ограничения в README, ARCHITECTURE и OpenSpec. Проверка: воспроизводимая приёмка каркаса; будущие API, Docker и деплой явно обозначены как планы.

## 2. Минимальный локальный прототип

- [ ] 2.1 Реализовать локальные submission/result-контракты с отдельными compilation/execution limits и фиксированный provider g++ C++23. Проверка: команда и динамическая линковка соответствуют REQ-21, runner не зависит от gRPC/S3 (REQ-26, AT-16); выбранные версии и сигнатуры задокументированы.
- [ ] 2.2 Реализовать workspace и отдельные isolate boxes для единственной компиляции и последовательных тестов, локальные stdout/stderr и исходные metadata. Проверка: воспроизводимый Linux-сценарий с тестами 8, 2, 5 без gRPC/MinIO, одна компиляция, порядок и независимость файлов сохранены (AT-01, AT-40).
- [ ] 2.3 Подготовить тестовый Docker-образ и очистку собственных областей прототипа. Проверка: локальный сценарий повторяется, boxes/workspace удалены, экспериментальные настройки отделены от production; обновлены инструкции прототипа (REQ-04, REQ-18–REQ-19).

## 3. Подтверждение среды и ресурсов

- [ ] 3.1 Подобрать и зафиксировать Linux/isolate/g++ версии, rootfs/mounts, non-root, delegation и непересекающиеся workspace/box IDs/cgroups (Q-09). Проверка: интеграционно подтверждены отсутствие сети, credentials, чужих файлов и доступа через proc/дескрипторы для обеих стадий, тестовые секреты отсутствуют в логах/результатах (AT-15, AT-62).
- [ ] 3.2 Реализовать обязательную startup-проверку cgroups v2, контроллеров/метрик, swap/OOM и pids. Проверка: несовместимая среда не принимает задания и завершается с ошибкой; совместимая обеспечивает групповой OOM без оставшихся процессов (AT-58–AT-60); результаты проверки среды записаны.
- [ ] 3.3 Определить и проверить mapping isolate/cgroups и границы/преобразования лимитов (Q-04–Q-05). Проверка: CPU всей группы, монотонный wall time, округление памяти, memory.peak, pids.events и отсутствие переполнений соответствуют AT-11–AT-14, AT-52–AT-61; один сигнал не доказывает превышение.
- [ ] 3.4 Реализовать лимиты отдельных потоков компиляции/исполнения и приоритет подтверждённых причин. Проверка: сохранены оба ограниченных частичных потока, компиляция при превышении не запускает тесты, ошибка теста не обрывает набор (AT-54–AT-56); mapping и ограничения задокументированы.

## 4. Локальный runner и storage

- [ ] 4.1 Довести локальные результаты и продолжение набора при ошибках процесса/инфраструктуры. Проверка: тесты классификации и локальные integration-сценарии сохраняют известные данные, явно отсутствующие значения и самостоятельный бюджет каждого теста (REQ-24–REQ-25, AT-08–AT-11, AT-42–AT-45).
- [ ] 4.2 Реализовать MinIO через AWSSDK.S3/IObjectStorage, env-only credentials, endpoint/path-style/region и локальную startup-валидацию (Q-08). Проверка: production SDK на MinIO без серверного региона, отсутствие fallback и успешный старт при недоступном storage (AT-62, AT-64–AT-66); документировать конфигурацию.
- [ ] 4.3 Реализовать два bucket по ролям, key/result_prefix и 32-байтовые SHA-256 без превращения S3-ключей в пути. Проверка: AT-17–AT-18, AT-47, AT-49 с корректными/некорректными хешами и префиксами; bucket не создаются агентом (REQ-15–REQ-16).
- [ ] 4.4 Реализовать три storage-попытки с задержками 200/500 мс, отключением скрытых повторов SDK и перезапуском скачивания с начала. Проверка: перечень временных/неповторяемых ошибок, отмена и фактическое число запросов production SDK соответствуют AT-19, AT-63; policy описана в документации.
- [ ] 4.5 Реализовать независимую публикацию артефактов и сохранение доступных ссылок, хешей и диагностик. Проверка: сбой одного потока не скрывает остальные, известный verdict не теряется, compiler upload failure сохраняет общий статус и продолжение по контракту (AT-21, AT-44, AT-46, AT-48).

## 5. Сквозной API и состояние задания

- [ ] 5.1 Оформить окончательный proto и техническую валидацию (Q-02–Q-03), сохранив IDs, bytes-хеши, профили лимитов и предварительно согласованные имена/коды. Проверка: AT-33, AT-39, AT-41, AT-47, AT-52, AT-57; новые лимиты числа тестов, запроса или входных файлов не вводятся, wire-контракт документирован.
- [ ] 5.2 Реализовать атомарное StartJob и сравнение всех разобранных полей текущего задания без обращения к storage. Проверка: подтверждение до завершения, повторы/конфликты при обработке и ожидании, приоритет проверок и конкурентное принятие (AT-02–AT-04, AT-34–AT-35).
- [ ] 5.3 Реализовать фоновую orchestration со storage/workspace/runner и состоянием в памяти, независимую от RPC. Проверка: сквозное задание выполняется после отключения/отмены/deadline, тесты идут в исходном порядке, результат удерживает ресурс без таймаута (AT-01–AT-02, AT-07, AT-38, AT-40); обновить описание pipeline.
- [ ] 5.4 Реализовать GetResult с NotReady/NOT_FOUND и атомарным извлечением до отправки ответа. Проверка: конкурирующие читатели, потерянный ответ, отсутствие восстановления результата, приоритет валидации и доступность во время остановки (AT-04–AT-06, AT-31–AT-33, AT-36).
- [ ] 5.5 Соединить уровни статусов/метрик/артефактов в финальном результате. Проверка: смешанный набор даёт общий Completed, ошибки до тестов/компиляции дают согласованные статусы без фиктивных тестов, необязательные значения явно отсутствуют (AT-20, AT-42–AT-46, AT-61).
- [ ] 5.6 Проверить повторное использование одного процесса/контейнера после выдачи результата и отсутствие истории ID. Проверка: AT-29–AT-30, AT-32, перезапуск теряет только состояние памяти, S3 остаётся доступным (AT-25); ограничения доставки результата описаны для мастера.

## 6. Отказы и эксплуатация

- [ ] 6.1 Реализовать начальную очистку только собственных остатков и завершение после ошибки очистки задания (Q-09/Q-11). Проверка: AT-50–AT-51, данные/статусы сохранены, среда повторно не используется, новый старт обязан пройти очистку; документировать механизм владения и аварийную очистку.
- [ ] 6.2 Реализовать штатную остановку с завершением набора и настраиваемым ожиданием результата 30 секунд по умолчанию, без общего таймаута задания. Проверка: AT-22–AT-24, AT-35–AT-36, отсчёт после подготовки результата/попыток очистки, выход после RPC или таймаута; обновить настройки приложения/контейнера.
- [ ] 6.3 Довести appsettings/env-приоритет, секции S3/Runner и конфигурацию только при старте. Проверка: AT-37, AT-72–AT-73, endpoint и workspace настраиваются, credentials только env, отсутствие hot reload; опубликовать проверенные примеры без секретов.
- [ ] 6.4 Подключить согласованные логи, отдельную трассу задания/стадий и метрики через platform без повторных providers/exporters. Проверка: AT-67, AT-70–AT-71, обязательный SERVICE_NAME, запрет содержимого/секретов и отсутствие job_id/test_id в метках метрик; имена инструментов и экспорт задокументированы.
- [ ] 6.5 Реализовать gRPC health на существующем порту и коды управляемого выхода. Проверка: AT-68–AT-69 при занятости, недоступном storage, остановке, ошибке старта и очистки; NOT_SERVING выставляется непосредственно перед остановкой сервера.
